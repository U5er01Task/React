## №24 - Решение

### Тема

Нормализация реляционных сущностей (Entity Normalization) и точечный патчер стейта за время $O(1)$.

### 1. Архитектурная проблема

В стандартных REST API ответы обычно возвращаются в виде плоских массивов:

```javascript
const rawUsers = [
  { id: "usr_1", name: "Анна", role: "admin" },
  { id: "usr_2", name: "Борис", role: "editor" },
];
```

Если хранить такой массив в стейте напрямую:

1. Поиск элемента по ID для обновления требует обхода `.map()` со сложностью $O(N)$.
2. Удаление элемента требует фильтрации `.filter()` со сложностью $O(N)$.
3. При частых обновлениях интерфейса на тысячах записей это приводит к падению производительности и сложностям с контролем ссылочной целостности.

### 2. Решение через нормализацию

Структура делится на:

- `byId`: Хэш-таблица (словарь), где ключ — это `id` сущности. Доступ, чтение и обновление происходят за время $O(1)$.
- `allIds`: Упорядоченный массив идентификаторов `['usr_1', 'usr_2']`, сохраняющий строгую последовательность отрисовки элементов на странице.

### 3. Эталонный код решения

```javascript
/**
 * Преобразует плоский массив в нормализованную структуру.
 * @param {Array<{ id: string }>} array
 * @returns {{ byId: Record<string, Object>, allIds: string[] }}
 */
function normalizeEntities(array) {
  if (!Array.isArray(array)) {
    throw new TypeError("Входной параметр должен быть массивом");
  }

  return {
    byId: Object.fromEntries(array.map((item) => [item.id, { ...item }])),
    allIds: array.map((item) => item.id),
  };
}

/**
 * Точечно обновляет поля сущности за O(1) с сохранением ссылочной целостности.
 * @param {Object} state - Нормализованный стейт
 * @param {string} id - ID обновляемой сущности
 * @param {Object} patch - Объект с новыми полями
 */
function patchEntityById(state, id, patch) {
  const currentEntity = state.byId[id];

  // Если сущности нет в словаре, возвращаем стейт без изменений
  if (!currentEntity) {
    console.warn(`Сущность с ID "${id}" не найдена.`);
    return state;
  }

  return {
    ...state,
    byId: {
      ...state.byId,
      [id]: {
        ...currentEntity,
        ...patch,
        updatedAt: Date.now(),
      },
    },
    // allIds не изменился — сохраняем старую ссылку на массив!
  };
}

/**
 * Удаляет сущность из словаря и индексного массива.
 * @param {Object} state
 * @param {string} idToDelete
 */
function removeEntityById(state, idToDelete) {
  if (!state.byId[idToDelete]) {
    return state;
  }

  // Деструктуризация с Rest для удаления ключа без мутации исходного объекта
  const { [idToDelete]: removed, ...remainingById } = state.byId;

  return {
    byId: remainingById,
    allIds: state.allIds.filter((id) => id !== idToDelete),
  };
}
```

### 4. Тестирование и верификация ссылочной изоляции

```javascript
// 1. Инициализация
const rawData = [
  { id: "usr_101", name: "Алексей", status: "active" },
  { id: "usr_102", name: "Мария", status: "pending" },
];

const normalizedState = normalizeEntities(rawData);

// 2. Точечное обновление пользователя usr_102
const nextState = patchEntityById(normalizedState, "usr_102", {
  status: "active",
});

// 3. Проверка ссылочной целостности (Критично для React.memo):
console.log(normalizedState !== nextState);
// true -> Корень изменился, React запустит рендер

console.log(normalizedState.byId["usr_102"] !== nextState.byId["usr_102"]);
// true -> Сущность usr_102 получила новый объект в памяти

console.log(normalizedState.byId["usr_101"] === nextState.byId["usr_101"]);
// true -> Ссылка на usr_101 осталась старой! Компонент этого пользователя НЕ будет перерисовываться

console.log(normalizedState.allIds === nextState.allIds);
// true -> Массив порядка ключей не менялся, ссылка сохранена
```
